# «Ничего не падает» — условия задания

Лабораторная работа к занятию 3 курса Kotlin Fullstack Developer 2026/2027.

## Задача

Реализуйте консольное приложение на Kotlin/JVM для обработки расписания. Опишите занятия так, чтобы через публичный API нельзя было создать некорректное состояние. Ошибки строк представьте типизированными результатами, а ошибки чтения файла — понятными сообщениями без стектрейса.

Начните с модели занятий. Для иерархии результатов разбора понадобится материал занятия 5 «Ошибки как данные».

## Репозиторий и данные

Сделайте Fork [репозитория](https://github.com/nikitosion/kfd-schedule-lab). В `app/src/main/kotlin` размещайте код приложения, в `app/src/test/kotlin` — тесты. В `samples/` находятся входные файлы и эталоны вывода. Настройка проекта и команды описаны в [README](../README.md).

## Формат и домен

Входной файл содержит расписание. Каждая строка описывает одно занятие и состоит ровно из пяти полей с разделителем `|`: дата, тип, тема, место, преподаватели через запятую. Внутри полей символ `|` не используется. Пустая строка считается ошибочной; в пустом файле строк нет.

```text
2026-10-05|ЛЕКЦИЯ|Классы и делегирование|ауд. 312|Портнов
2026-10-08|ПРАКТИКУМ|Моделируем домен|ауд. 312|Анохин
2026-10-15|СДАЧА|Устная сдача №1|ауд. 401|Портнов,Степанова
2026-10-19|ОТМЕНА|Лекция перенесена на 20.10|—|—
```

Создайте четыре конечных типа в sealed-иерархии `Session`. Общие свойства: `date: LocalDate` и непустой `topic`. У лекции и практикума есть место и хотя бы один преподаватель; у сдачи — место и не менее двух разных преподавателей. У отмены **нет свойств** места и преподавателей: в файле оба соответствующих поля содержат `—`.

Внешние пробелы полей/имён, управляющие символы, пустые элементы списка, повторные имена и тире вместо места/преподавателя действующего занятия отклоняются. Регистр значим; имена сравниваются посимвольно. Внутренние пробелы в теме, месте и имени разрешены. Ничего автоматически не исправляйте. Дата — строго четыре цифры года, две месяца, две дня; год 0001–9999, день существует.

Проверки в `init` защищают все публичные пути создания, включая `copy`. Изменение переданного снаружи `MutableList` не должно менять готовое занятие: нужна защитная копия и неизменяемый доступ либо собственный неизменяемый тип.

## Ошибки строки

Представьте результат разбора своей sealed-иерархией: успех с занятием или вариант отказа с номером строки (с единицы) и структурированными данными. Не храните готовый текст либо `Throwable` вместо причины. Напишите отдельную функцию, которая превращает вариант отказа в текст сообщения.

Первая сработавшая проверка определяет **единственную** ошибку строки:

1. Нет `|`, в том числе строка пустая → неверный разделитель.
2. Число полей не пять, конечные пустые поля сохраняются → неверное число.
3. Первое пустое/пробельное поле в порядке дата, тип, тема, место, преподаватели → пустое поле.
4. Неверный формат/значение даты → дата.
5. Тип вне четырёх разрешённых → неизвестный тип.
6. СДАЧА и менее двух непустых элементов, отличных от `—` → недостаточно преподавателей.
7. Остальные ограничения домена: пробелы/управляющие символы, поля отмены, место, состав/дубликаты имён. Для них предусмотрите отдельные сообщения.

Обязательные сообщения дословны; параметры подставляются из входа:

```text
строка N: несуществующая дата «2026-13-45»
строка N: пустое обязательное поле «дата»
строка N: неверный разделитель полей
строка N: неизвестный тип занятия «СЕМИНАР»
строка N: у типа «СДАЧА» должно быть не менее двух преподавателей, получено 1
строка N: полей 6, ожидалось 5
```

Имена полей: `дата`, `тип`, `тема`, `место`, `преподаватели`. Кавычки — `«»`. Например, `2026-13-45|СЕМИНАР|Т|а|И` даёт ошибку даты, а `|СЕМИНАР|Т|а|И` — пустого поля.

## CLI и вывод

```text
schedule period --file PATH --from YYYY-MM-DD --to YYYY-MM-DD
schedule type --file PATH --type ЛЕКЦИЯ
schedule errors --file PATH
```

Порядок пар параметр/значение произволен; каждый параметр обязателен и встречается ровно один раз. Неизвестные/лишние параметры, отсутствие значений, повтор параметра, неизвестная команда, недопустимая дата/тип, `from > to` дают код 2. Синтаксис `--key=value` не поддерживается. Для имени файла, начинающегося с `--`, используйте путь `./--имя`. Других аргументов нет.

`period`: печатает занятия в диапазоне включительно: дату, тип, тему и место. `type`: выбирает занятия одного из четырёх типов и добавляет преподавателей к тем же полям. Имена преподавателей разделяются запятой с пробелом. Вместо места и преподавателей у отмены печатается `—`. `errors`: печатает сообщения обо всех отклонённых строках.

Результаты и сообщения об ошибках выводите в консоль через `println`.

Сохраняется порядок файла. Ошибочные строки пропускаются в `period/type`, но учитываются в коде возврата, даже если не попадают в фильтр. Полный файл проверяется всегда. Итоги: `Всего: N` для `period/type`, `Всего отклонено: K из M` для `errors`. N — число напечатанных занятий, M — всех физических строк, K — отказов. Итог нужен и для нулевых результатов.

Разделяйте поля строкой ` | ` — по одному пробелу с каждой стороны разделителя. Каждое занятие выводите с новой строки. Не добавляйте заголовок таблицы, не обрезайте значения и не сортируйте строки. Пример результата `period`:

```text
2026-10-05 | ЛЕКЦИЯ | Классы и делегирование | ауд. 312
2026-10-08 | ПРАКТИКУМ | Моделируем домен | ауд. 312
Всего: 2
```

Полные примеры вывода находятся в файлах `*.expected`.

`clean.expected` относится **именно** к `period --file samples/clean.txt --from 2026-09-28 --to 2027-05-13`.

| Код | Условие | Вывод в консоль |
|---:|---|---|
| 0 | Всё обработано, нет отклонённых строк | результат и итог |
| 1 | Всё обработано, есть отклонённые строки | результат и итог |
| 2 | Неверные аргументы или ошибка чтения файла | понятное сообщение на русском |

Если файл не найден или недоступен для чтения, выведите понятное сообщение на русском и завершите команду с кодом 2. Если чтение прервалось после нескольких строк, уже выведенный результат сохраняется.

Подсказки по чтению файла, неизменяемым коллекциям и тестам — в [памятке](student-guide.md).
