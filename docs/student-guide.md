# Памятка по реализации

## Чтение файла

Для обработки файла по строкам можно использовать `forEachLine`:

```kotlin
import java.io.File
import java.io.IOException

fun printFile(path: String) {
    try {
        File(path).forEachLine { line ->
            println(line)
        }
    } catch (e: IOException) {
        println("Не удалось прочитать файл: $path")
    }
}
```

Блок получает очередную строку, а файл закрывается автоматически. В приложении передавайте строку в свой парсер и обрабатывайте результат разбора. Номер строки удобно хранить в отдельном счётчике.

## Вывод в консоль

Для результата и сообщений об ошибках используйте `println`. Например:

```kotlin
println("2026-10-05 | ЛЕКЦИЯ | Классы и делегирование | ауд. 312")
println("Всего: 1")
```

## Неизменяемые коллекции

`val teachers: List<String>` не гарантирует неизменяемость: снаружи может остаться ссылка на исходный `MutableList`. `toList()` отделяет список от исходного, но возвращённую копию тоже нужно защищать от изменения. В JVM-проекте для этого подходит `java.util.List.copyOf`. Проверяйте инварианты по сохранённой копии.

Конструктор и `copy()` у `data class` должны сохранять одни и те же инварианты. У отменённого занятия не объявляйте свойства места и преподавателей.

## Тесты разбора

Размещайте тесты в `app/src/test/kotlin`. Метод теста помечается `@Test`; `assertIs` помогает проверить вариант результата, `assertEquals` — его данные или сообщение. Номер строки передавайте в парсер явно.

Начните с коротких строк: корректное занятие, пустое поле, несуществующая дата, несколько дефектов одновременно. Ожидаемый текст задавайте явно, чтобы тест не повторял реализацию форматтера. В `samples/*.expected` находятся примеры полного вывода.

Команда для тестов: `.\gradlew.bat test` на Windows или `bash ./gradlew test` на Linux/macOS.
